# edap-grpc vs grpc-java 端到端对比（packed int V11 之后复跑）

生成时间: 2026-11-14

批次: `matrix-20261114-packedv11-{1,2,3}.md`（各 4 臂 × 4 轮拉丁方）
对照基线: `matrix-20261113-frameinline-{1,2,3}.md`（= `matrix-summary-20261113-frameinline.md` 那批）
测量口径: 预热 1000ms + 测量窗口 3000ms；两边流控窗口对齐到 8MB
（`-Dedap.grpc.connWindow` / `-Dbench.google.connWindow`）

---

## 〇、一句话结论

**这一轮没有端到端变化可测。**
第九轮把 packed int 编码改成了 V11（单遍 + 局部下标 + 热路径零方法调用，微观 **-20%**），
但 **gRPC 基准的负载是「一个 bytes blob 字段」，根本不走 packed 路径**
⇒ 端到端 12 档全部落在 **±1.5%**（= 机器噪声地板）内。

⇒ **这批数据的作用是「确认现状」**：帧头内联之后的端到端优势**依然成立**，
**edap 在全部 12 档仍然全面领先 grpc-java（1.20x ~ 2.12x）**。

## 四、跑法

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17
cd /Volumes/Data/NetBeansProjects/edap/edap-grpc-parent/edap-grpc-benchmark
mvn -o -q dependency:build-classpath -Dmdep.outputFile=target/cp.txt -Dmdep.includeScope=runtime
for i in 1 2 3; do
  $JAVA_HOME/bin/java --add-opens java.base/java.lang=ALL-UNNAMED --add-opens java.base/java.nio=ALL-UNNAMED \
    --add-opens java.base/sun.nio.ch=ALL-UNNAMED --add-opens java.base/java.util=ALL-UNNAMED \
    -Dedap.grpc.connWindow=8388608 -Dbench.google.connWindow=8388608 \
    -cp "target/classes:$(cat target/cp.txt)" io.edap.grpc.benchmark.BenchMain \
    --warmup 1000 --measure 3000 --rounds 4 \
    --out doc/bench/matrix-20261114-packedv11-$i.md
done
```

> ⚠ 跑基准期间不要中途 `mvn install` —— 基准的 classpath 指向 `~/.m2` 的 jar。
> ⚠ 机器 loadavg 常 5~11 ⇒ **绝对值不可跨批次比较**，只看同批内的相对关系与 G→G 对照列。
> ⚠ 每批约 13 分钟（4 臂 × 4 轮 × 12 个 (负载,并发) 组合 × 4 秒）。
